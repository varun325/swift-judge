`throws(BankError)` (SE-0413) tells callers exactly which error type can come out, so `catch` binds `error` as `BankError` and the switch is exhaustive. In a plain function body the `do` infers its error type; **inside a closure** you spell it out with `do throws(BankError) { … }` — otherwise `error` is `any Error`. Your notes' `withdraw` bug (refusing when `funds == amount`) is avoided with `<=`.
