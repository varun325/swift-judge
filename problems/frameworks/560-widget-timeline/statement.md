A widget can't run code on demand; you hand WidgetKit a **timeline** of entries up front. For a "next event" widget, create an entry at `now` and at every hour boundary for the next `hours` hours; each entry shows the next upcoming event (`[title, ISO date]`) at that moment, or `"free"`. Collapse consecutive entries showing the same content (keep the earlier one). Return `"<HH:mm> <title|free>"` (UTC) plus a final `"reload after <HH:mm>"` = time of the last entry + 1 hour (the `.after` reload policy).
