A `~Copyable` value can't be implicitly copied — `let b = a` **moves** it, and using `a` afterwards is a compile error. `borrowing` parameters get temporary read access; `consuming` ones take ownership, so after `handle.close()` the handle is gone and its `deinit` runs at the end of `close()` (seeing `closed == true`). Structs with `deinit` — impossible for copyable structs — are how Swift models unique resources. (`discard self` can skip `deinit` entirely, but only for types whose stored properties are trivially destroyed — not `String` or class references.)
